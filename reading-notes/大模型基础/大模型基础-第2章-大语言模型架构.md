# 第2章 大语言模型架构

---

## 本章导读

数据与算力爆发后，语言模型进入 **LLM** 时代。本章围绕三条主线展开：

1. **为什么“大”**：数据 + 参数如何带来能力增强与涌现  
2. **三种主流架构**：Encoder-only / Encoder-Decoder / Decoder-only（均基于 Transformer）  
3. **非 Transformer 探索**：SSM（RWKV、Mamba）与 TTT，应对长序列瓶颈  

---

## 2.1 大数据 + 大模型 → 新智能

“大”同时指：**模型规模大、训练数据大、能力强**。

### 发展三阶段（至约 2024 年）

| 阶段  | 时间        | 标志                                      |
| --- | --------- | --------------------------------------- |
| 萌芽期 | 2017–2018 | Transformer、BERT、GPT-1                  |
| 发展期 | 2019–2022 | GPT-2/3、T5、BART、各类变体                    |
| 突破期 | 2022 起    | ChatGPT、GPT-4、Gemini、Claude、ChatGLM、百川等 |

### 2.1.1 能力增强：扩展法则（Scaling Laws）

规模变大带来更强拟合能力，但也抬高算力与存储成本。扩展法则用来指导 **N（参数）** 与 **D（数据）** 如何配计算预算 **C**。

#### Kaplan–McCandlish（OpenAI, 2020）

- 单独看：损失随 \(N\)、\(D\) 增大而下降（幂律关系）  
- 算力关系近似：\(C \approx 6ND\)  
- 最优分配倾向：**模型规模增速略快于数据**  
  - \(N_{opt} \propto C^{0.73}\)，\(D_{opt} \propto C^{0.27}\)  
  - 算力 ×10 ≈ 模型 ×5.37、数据 ×1.86  

#### Chinchilla（DeepMind, 2022）

- 联合损失形式：\(L(N,D)=E+A/N^\alpha+B/D^\beta\)  
- 最优分配：**N 与 D 几乎同等重要**  
  - \(N_{opt} \propto C^{0.46}\)，\(D_{opt} \propto C^{0.54}\)  
  - 算力 ×10 ≈ N、D 各约 ×3.16  
- 经验法则：理想 Token 数约 **20× 参数量**（如 7B → ~140B Token）  
- 启示：不再只堆参数，要 **优化“参数–数据”比例**（PaLM 2 等后续工作也呼应这一点）

### 2.1.2 能力扩展：涌现能力（Emergent Abilities）

规模跨过阈值后，可能出现 **非平滑、突变式** 新能力（类似“相变”），而非在小模型上平滑插值得到。典型包括：

| 能力         | 要点                 |
| ---------- | ------------------ |
| 上下文学习（ICL） | 靠提示/示例完成任务，少改或不改权重 |
| 常识推理       | 日常事实与因果推断          |
| 代码生成       | 理解需求、写码、部分场景下修复/优化 |
| 逻辑推理       | 条件/多步推理并保持一致性      |

GPT 系列上常见观察：早期版本弱 → 中等规模局部可用 → **百亿～千亿级** 才在复杂任务上明显变强。

**伴随挑战**：可解释性、安全与隐私、伦理公平、巨量算力等。

## 2.2 大语言模型架构概览

绝大多数 LLM 以 **Transformer + 自注意力** 为核心，衍生三类架构。

### 2.2.1 三类架构（设计理念）

#### Encoder-only

- 只用编码器：输入编码 → 多层 Encoder Block → 任务头  
- 输入：分词 → Embedding → 位置编码  
- 预训练与下游可共用编码栈，**任务头按任务定制**  
- 生成时若硬套“逐 Token 预测”，每次常需重算整段表示，效率与连贯性受限  

#### Encoder-Decoder

- 编码器给输入上下文；解码器含：掩码自注意力 + **交叉注意力** + FFN  
- 训练：Teacher Forcing，用真值前缀预测下一 Token  
- 推理：从 `[START]` 自回归采样，直到结束符或达最大长度（串行）  

#### Decoder-only

- 去掉编码器与交叉注意力，仅用掩码解码栈做 **自回归 LM**  
- 结构更轻、易扩展；当前主流生成式大模型多属此类  

### 2.2.2 功能对比

#### 注意力形态

| 架构              | 注意力特点                     |
| --------------- | ------------------------- |
| Encoder-only    | 双向“满”注意力，看全句上下文           |
| Encoder-Decoder | 编码双向 + 解码下三角掩码 + 交叉注意力读编码 |
| Decoder-only    | 仅下三角掩码自注意力（单向）            |

#### 适用任务倾向（同等规模下）

| 架构              | 更擅长             | 短板/代价                  |
| --------------- | --------------- | ---------------------- |
| Encoder-only    | NLU：分类、情感、NER 等 | 原生生成弱                  |
| Encoder-Decoder | 条件生成：翻译、摘要、QA   | 参数与计算更重                |
| Decoder-only    | 开放生成、对话、通用任务    | 小规模时理解复杂输入可能弱于 Enc-Dec |

**趋势**：规模与数据上来后，**Decoder-only 任务泛化占优**，成为事实上的“大一统”候选（GPT-3/4 等）。

### 2.2.3 历史演变

```
Encoder-only 走红（BERT 理解强）
        ↓ 生成需求上升
Encoder-Decoder 盛行（Seq2Seq）
        ↓ 参数易扩展 + AIGC
Decoder-only 主导（GPT-3 之后）
```

更迭主因：生成能力需求 + 计算效率/可扩展性差异。Enc-only 仍在部分判别任务中有用；Enc-Dec 在开源社区仍活跃。

## 2.3 Encoder-only 架构

### 2.3.1 核心：双向编码器

- 融合前向/后向信息 → **动态上下文嵌入**（相对 Word2Vec/GloVe 静态向量）  
- 不直接生成，但为理解与推理提供强表示  
- 代表：BERT、RoBERTa、ALBERT、ELECTRA  

### 2.3.2 BERT（2018.10，Google）

**结构**

| 版本    | 层数  | 隐层   | 头数  | 约参数   |
| ----- | --- | ---- | --- | ----- |
| Base  | 12  | 768  | 12  | 1.1 亿 |
| Large | 24  | 1024 | 16  | 3.4 亿 |

**预训练数据**：BookCorpus + 英文维基，约 33 亿 Token / ~15GB  

**预训练任务**

1. **MLM**：约 15% Token 掩码/随机替换，完形填空式预测（只对改动位置计损）  
2. **NSP**：两句是否原文连续（各 50%）  

特殊标记：`[CLS]` 聚合整段；`[SEP]` 分句边界。

**下游用法**：用 `[CLS]` 向量接分类头；QA 用问题+段落拼输入，预测答案起止等。

### 2.3.3 BERT 衍生

#### RoBERTa（2019.07，Meta）

- 结构近似 BERT；更大语料（~160GB）、更长训练、更大 batch  
- **去掉 NSP**；**动态掩码**（多副本不同掩码）  

#### ALBERT（2019.09，Google）

- **嵌入因子分解**：\(V\times H \to V\times E + E\times H\)（E 如 128）减参  
- **跨层参数共享**：一层参数复用多层  
- NSP → **SOP（句序预测）**  
- Base 约 0.12 亿参数量级，显著更省内存  

#### ELECTRA（2020.03）

- **生成器–判别器**：生成器做 MLM 填空；判别器用 **RTD**（每个 Token 是否被替换）  
- 判别器对 **全部 Token** 学习，样本效率高于只训 15% 掩码位  

#### 小结表（书中对比要点）

| 模型      | 约参数（亿）           | 语料量级       | 预训练         |
| ------- | ---------------- | ---------- | ----------- |
| BERT    | 1.1 / 3.4        | ~15GB      | MLM+NSP     |
| RoBERTa | 1.2 / 3.5        | 160GB      | Dynamic MLM |
| ALBERT  | 0.12–2.2         | ~15GB      | MLM+SOP     |
| ELECTRA | 0.28 / 2.2 / 6.6 | 约 20–200GB | RTD         |

共性：参数多止步于约 6.6 亿级，主攻 **理解/判别**，难以撑起当前生成式浪潮。

## 2.4 Encoder-Decoder 架构

### 2.4.1 结构要点

- 编码：双向自注意力 + FFN → 上下文表示  
- 解码：掩码自注意力 + **交叉注意力**（Q 来自解码，K/V 来自编码）+ FFN  
- 擅长翻译、摘要、问答等 **有条件 Seq2Seq**  

### 2.4.2 T5（2019.10，Google）

- 理念：**一切 NLP 任务统一为 Text-to-Text**（输入前缀指示任务，可视为早期 Prompt）  
- 版本：Small / Base / Large / 3B / **11B**  
- 数据：**C4**（Common Crawl 清洗），约 **750GB**  
- 预训练：**Span Corruption**——约 15% Token，常以连续 3-Token span 掩为一块再还原  
- 下游：零样本 Prompt 或微调；衍生 mT5、T0、Flan-T5 等  

### 2.4.3 BART（2019.10，Meta）

- 标准 Transformer Enc-Dec；Base ~1.4 亿，Large ~4 亿  
- 语料与 RoBERTa 类似（~160GB）  
- **多噪声去噪预训练**：Token Masking / Deletion / Text Infilling / Sentence Permutation / Document Rotation  
- 兼顾理解与生成；衍生如 mBART  

#### 小结表（量级）

| 模型    | 约参数         | 语料量级         |
| ----- | ----------- | ------------ |
| T5    | 0.6 亿–110 亿 | 750GB        |
| mT5   | 3 亿–130 亿   | 9.7TB        |
| T0    | 30–110 亿    | ~400GB       |
| BART  | 1.4–4 亿     | ~20–160GB 量级 |
| mBART | 0.4–6.1 亿   | ~1TB         |

相对 Enc-only：参数上限更高，条件生成更强。

## 2.5 Decoder-only 架构

开放式生成往往输入简单甚至无条件输入，完整编码器未必必要 → **仅解码器 + 自回归** 更灵活、更易扩展。

代表路线：

- **GPT 系列**：起步早、性能标杆，后期闭源  
- **LLaMA 系列**：开源生态、强调优质大数据  

### 2.5.2 GPT 系列（五阶段）

| 阶段   | 模型                       | 约参数 / 语料              | 关键点                       |
| ---- | ------------------------ | --------------------- | ------------------------- |
| 初出茅庐 | GPT-1 (2018)             | 1.17 亿 / ~5GB         | Decoder-only + 下一词预测；需微调  |
| 小有所成 | GPT-2 (2019)             | 至 15 亿 / 40GB WebText | 零样本能力增强                   |
| 崭露头角 | GPT-3 (2020)             | 至 **1750 亿** / ~1TB   | **ICL** 涌现，少样本即可          |
| 蓄势待发 | InstructGPT / Codex 等    | —                     | **RLHF**、代码继续预训练；DPO 简化对齐 |
| 一鸣惊人 | ChatGPT / GPT-4 / GPT-4o | 细节闭源                  | 对话产品化、多模态、LLMaaS          |

**GPT-1 vs BERT-Base**：层数等类似，本质差在 **单向掩码注意力 vs 双向注意力**。

**RLHF 三步**（InstructGPT）：

1. 监督微调（示范回答）  
2. 训奖励模型（人工排序偏好）  
3. 强化学习（如 PPO）用奖励优化策略  

**DPO**：直接用偏好对优化策略，省略单独奖励模型 + 复杂 RL，更省算力。

**GPT-4 / 4o**：更强推理与编程；图文等多模态；4o 强调延迟与多语言体验。自 ChatGPT 起细节闭源。

### 2.5.3 LLaMA 系列（Meta）

路线差异：GPT 主升 **规模+数据**；LLaMA 更强调相对可控参数 + **更大更高质数据**（Chinchilla 思路）。

| 版本                | 参数档（亿）               | 语料量级  | 要点                      |
| ----------------- | -------------------- | ----- | ----------------------- |
| LLaMA-1 (2023.02) | 67 / 130 / 325 / 652 | ~5TB  | RoPE、SwiGLU、Pre-Norm 等  |
| LLaMA-2 (2023.07) | 70 / 130 / 340 / 700 | ~7TB  | SFT + RLHF；大模型用 **GQA** |
| LLaMA-3 (2024.04) | 80 / 700             | ~50TB | 词表扩大约 3×；更多代码与多语；性能大幅跃升 |

**衍生生态（三类）**

- 性能改进：Alpaca、Vicuna、Guanaco（QLoRA）等  
- 垂域：CodeLLaMA、LawGPT、GOAT（数学）、金融问答等  
- 多模态：LLaVA、MiniGPT-4 等

## 2.6 非 Transformer 架构

### 痛点

Transformer 注意力对序列长度常呈 **二次复杂度**，长上下文贵。传统 RNN 线性复杂度但长程依赖弱、难并行。

两条现代方向：

1. **SSM（状态空间模型）**  
2. **TTT（测试时训练 / Test-Time Training）**  

目标：对长度近似 **线性复杂度**，又缓解经典 RNN 问题。

### 2.6.1 状态空间模型 SSM

源自控制论动力系统：用状态变量刻画连续时间演化；可离散成：

- **递归形式**：推理高效（类 RNN），训练难并行  
- **卷积形式**：训练可并行（时不变核），自回归推理不便  

实践：**训练用卷积，推理用递归**。变体差异多在离散化方式与 \(A\) 矩阵定义（如 S4 + HiPPO）。

#### RWKV

- 结合 RNN 推理效率与 Transformer 式可并行训练  
- 核心：**时间混合 + 通道混合**；WKV 可理解为 **两个 SSM 之比**  
- 权重随时间衰减；可扩到约 **14B** 级非 Transformer  
- 长上下文强，但仍有局限 → 引出 Mamba  

#### Mamba

- 问题：纯时不变 SSM 对信息密集文本偏弱  
- **选择机制**：\(B,C,\Delta\) 等随输入变化（内容选择）  
- **硬件感知算法**：内核融合、并行扫描、重计算（HBM/SRAM）  
- 模块同质堆叠；训练/推理随长度近似线性；宣称推理吞吐可显著高于同规模 Transformer；可处理极长序列  

### 2.6.2 TTT（测试时训练）

SSM 把上下文压进 **固定长度隐状态**，超长后易饱和（如 Mamba 在很长上下文上困惑度难再降）。

TTT 思路：

- 用 **模型参数本身** 记上下文  
- **推理时对每个测试样本** 做内部循环梯度更新（边“训”边推）  
- 预训练：外部循环 = 常规下一词预测；内部循环 = 自监督更新隐状态  
- 相对 SSM：表达力更强，适合超长上下文；复杂度仍可保持线性量级
